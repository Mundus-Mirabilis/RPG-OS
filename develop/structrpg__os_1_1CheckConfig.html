Detailed Description

Describes HOW a check is resolved, as loaded from a ruleset's check_types.

Why own its strings?
CheckConfig is built from ruleset JSON and must outlive the parse, so it owns its std::string members. That makes it a self-contained value the universal engine can hand to the dispatcher without any lifetime dependency on the Ruleset that produced it — and a stable thing for generated code to mirror with constexpr configs.
