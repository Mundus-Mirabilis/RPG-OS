Detailed Description

Loads and validates a ruleset JSON document.

Why a static-only class (namespace-like)?
Loading is a pure function of the JSON input: it has no state worth keeping in an object. A static-only interface communicates that and keeps the API trivially testable — every parse stage is independently checkable via the validation errors it raises.

Ruleset rpg_os::RulesetLoader::load ( const Json &  root)
inlinestatic

Parses and validates root. Throws std::invalid_argument on any error.

Why throw instead of returning a result?
A ruleset that cannot be loaded is unrecoverable for the engine that hosts it; failing loudly with a descriptive message is clearer than threading an error code through every consumer.

void rpg_os::RulesetLoader::validate ( const Ruleset &  ruleset)
inlinestatic

Re-validates a loaded ruleset; throws std::invalid_argument on error.

Why is validation re-runnable?
Loading already validates, but a ruleset may be edited after load (e.g. by tooling or a live-edit app). Re-running validation lets such a caller check the mutated model without re-parsing from JSON.
