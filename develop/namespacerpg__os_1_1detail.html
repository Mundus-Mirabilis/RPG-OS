One combatant's action: resolves the attack check against the defender and, on a hit, rolls and applies the damage through the event pipeline. Returns true when the defender is reduced to 0 (or below) hit points.

Why keep this in a detail namespace?
It is a single round of a fight — meaningful only inside the loop below. Hiding it in detail keeps the public surface of the header to the reusable entry points (makeCombatantSpec, runFight) while still making the loop readable.

std::array< uint32_t, 8 > rpg_os::detail::entropyWords ( )
inlinenoexcept

Collects 8 entropy words from the OS random device (when available), mixed with the high-resolution clock, the process id and an ASLR-random stack address.

Why mix several sources?
std::random_device is not guaranteed to be truly random — on some implementations (notably MinGW) it is a deterministic PRNG. Mixing in the clock, the stack address (randomised by ASLR) and the process id keeps the seed genuinely unpredictable even where the random device is weak, while the try/catch means a missing device degrades to "still varied" instead of aborting.

The process id, used as one entropy source (0 when unavailable). Kept behind platform guards so the entropy mix below works on Windows, POSIX, and exotic targets alike — a missing process id just weakens entropy slightly, it never breaks the build.
