constexprnoexcept

Clamps value into the inclusive range [lo, hi].

Why not std::clamp?
std::clamp returns a const double& to one of its arguments, which forces callers to keep temporaries alive; a by-value helper has no such lifetime subtlety and is trivially inlined. Hand-rolling the comparison also avoids the NaN pitfall being a silent pass-through (NaN compares false and thus returns lo, matching the clamp semantics rulesets want).

◆ floor()

constexpr double rpg_os::math::floor ( double  value)
constexprnoexcept

Floors a value (matches std::floor).

Why not just return std::floor?
C++23 makes std::floor constexpr, but older libstdc++ (GCC < 13, e.g. the clang toolchain on the CI runner) has not implemented that, so a static_assert on this helper would not compile there. This manual form is constexpr on every toolchain and matches std::floor exactly for all finite values in the int64 range.

◆ floorDiv()

constexpr int rpg_os::math::floorDiv ( int  a,
int  b 
)
constexprnoexcept

Integer floor division: the largest integer <= a/b (handles negative operands exactly like floor applied to the rational a/b).

Why a dedicated integer division?
The generated specific-mode code compiles formula divisions to integer arithmetic (no floating point in the hot path). A plain C++ / truncates toward zero, which is not floor for negatives; this helper makes floor(a / b) in a formula byte-identical to the universal double evaluator's math::floor(a / b).
When can a cheaper form be used?
Ruleset stats are overwhelmingly non-negative (attributes and skills are stored as unsigned bytes), so most formula divisions never see a negative numerator. For those floorDivN / ceilDivN / roundDivN reduce to a single integer division. Only formulas that can legitimately go negative (e.g. D&D ability modifiers like (STR - 10) / 2) need the general form here.

constexpr int rpg_os::math::floorDivN ( int  a,
int  b 
)
constexprnoexcept

Non-negative floor division: a / b floored, valid only when a >= 0 and b > 0. For non-negative operands a plain C++ / (which truncates toward zero) already equals floor, so this is a single division with no sign handling — the fast path for ruleset stats that never go negative.

Why a separate function instead of assuming it inside floorDiv?
Some formulas (D&D ability modifiers) do produce negative numerators; the general floorDiv keeps those exact. This variant documents and exploits the non-negativity precondition so callers who know their values are non-negative (the generated code proves it) pay nothing extra.

◆ toStat()

constexpr int32_t rpg_os::math::toStat ( double  value)
constexprnoexcept

Converts a formula result (double) to an integer stat value.

Why truncation and not rounding?
Formula text is expected to apply floor/ceil/round explicitly where a fractional result must be reduced — the ruleset author, not the engine, decides the rounding policy per stat (e.g. D&D ability modifiers floor, while hit-point averages round down by convention). This helper therefore only performs the type conversion, truncating toward zero, so the engine never silently imposes a rounding rule the ruleset did not ask for.
